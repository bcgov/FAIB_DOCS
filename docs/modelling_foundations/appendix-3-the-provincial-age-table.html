17 Appendix #3: The Provincial Age Table

17.1 Introduction

One of the primary inputs to all timber supply models is a starting age condition for the analysis forest. Age is used for yield interpolation, stand availability and merchantability assessments and forest cover constraints. In STSM the initial age variable is updated and/or reset each time step depending on inter-step disturbance and succession.

In order to standardize the creation of age inputs for forest landscape modelling I’ve created a provincial age table.

The provincial age table links to spatial data via gr_skey/ogc_fid reference keys with a unique age value for each feature_id in the province.

17.1.1 Age

The provincial age data set combines multiple age related data sources into a single table then assigns the appropriate age to a rasterization column based on a hierarchical selection driven by data quality. Ages are assigned based on following logic:

  1. Ground data collected as part of provincial monitoring programs represent the highest order age estimates
  2. RESULTS based ages estimates for managed stand features
  3. FAIB’s Consolidated Cut block change detection age estimates for features
  4. VRI photogramatic age estimates for all other features

The ages have been depleted to the fall of 2025 then updated to the 2025.

17.1.1.1 Data Sources

The following is a description of the data sources in order of application:

17.1.1.1.1 Ground Sample Data

Provincial forest resource monitoring programs include:

  • Provincial Change Monitoring Inventory (CMI)
  • Provincial Young Stand Monitoring (YSM)
  • National Forest Inventory (NFI) programs.

These programs are provincial in scope and their plots are located on a standard 20 km grid or an intensification of this grid. These plots are measured at regular time intervals and use well known sampling methods. The main strengths of this program are the ease of re-measurement and statistically sound design using fixed-radius plots located at each grid intersection. It is important that these provincial programs are distinguished from location-specific CMI and YSM plots that have been established by forest companies in the past. Vegetation Resource Inventory (VRI) audits were intended to verify key spatial inventory attributes estimated during photo interpretation, temporary plots were randomly established within mapped polygons in mature stands. Comparisons of this ground data to the photo estimation attributes helped determine confidence in the inventory for TSR. The main strength of this program was the efficiency in capturing variability within a polygon with the 5-point cluster plot design and the probability proportional to size with replacement (PPSWR) plot location. Its weaknesses was that the plots are not designed to be re-measured (which is often required) and have limited flexibility in the use of the data.

Ground sample data used to calibrate the inventory and yield estimates is collected and collated at the end of every field season and is available to the public via the BC Geographic warehouse. The data is linked directly to the feature_id of the inventory that the sample plot falls in and consequently represents the best representation of age for that feature.(further discussion of the sampling process and age derivation for the feature_id as a whole.

The follow script mines the published ground sampling data. Two tables are needed to extract plot ages:

  1. faib_compiled_spcsmries_site age.csv which contains sampled ages by species for each plot identified by its cluster_id and site_identifier
  2. faib_sample_by_visit.csv which identifies the measurement year of each plot and joins to faib_compiled_spcsmries_site age.csv via cluster_id and the Feature_id_lookup.csv via the site_identifier

(Additionally the faib_header.csv contains the spatial ccordinates for the plots and can be used to recreate them for further geoprocessing.)

Ages are summarized by cluster_id and the latest measurement is used to calculate the median for the plot. Ages are then adjusted based on the year of the survey then linked to the underlying vri polygon via the feature_id lookup. There are 10962 features with ground sample ages.

17.1.1.1.2 Permanent Sample Plots

Permanent Sample Plots (PSPs) are purposefully located across a gradient of different forest types and are used to support development and testing of growth-and-yield models in unmanaged stands. They also provide a long-term biological baseline for how forest stands grow and develop. The main strength of this program is that it has been operational for over 90 years with some plots having 12 re-measurements. The subjective location of plots along a gradient of forest types is needed for model development, but limits the utility in monitoring average forest condition.

Calculating age from PSP follows the same process as the ground samples. Multiple PSPs can occur in a single feature_id therefore an additional summary at the feature level must occur to create a single age for a given inventory polygon. There are 4155 features with PSP ages.

17.1.1.1.3 Consolidated Cutblocks

The Consolidated Cut blocks (CCB) data set spatially combines forest harvesting data from multiple data sets (i.e . RESULTS, Forest Cover Inventory (VRI) and Landsat satellite change detection). The data set depicts historical cut blocks on all land owner types that are recorded in Ministry of Forest’s system and includes an estimate of the year of harvest. The CCB is updated quarterly to capture the most recent harvest activity.

Landsat satellite change detection datasets (created annually from 1999 to 2025 and quarterly since 2025) have been incorporated into the consolidated cutblocks dataset to identify harvest in those areas not reported in RESULTS (e.g. unreported harvest, harvest in private lands and harvest in licence types without reporting obligations). For cutblocks detected using this method, harvest start and completion dates are estimated using regularly monitored satellite imagery. More information on the change detection process can be found here.

The RESULTS system contains the reported harvest and silviculture obligations from licensees on record going back to 1900. Licensees are required to report attribute information of all harvesting activity in the previous fiscal year to RESULTS by June 1st each year. Spatial harvest data is only required to be reported by June 1st after the year harvesting has been completed, although licensees may voluntarily submit spatial harvest information before harvest completion of an opening. As a result, openings with harvest activity occurring over multiple years may take multiple years after harvesting has started before spatial information appears in the RESULTS system. The consolidated cutblocks dataset includes only RESULTS cutblocks with spatial information in the system on the date the dataset is run (quarterly). This results in some mult-iyear cutblocks appearing in dataset years after harvest start year of the RESULTS submission.

RESULTS has cutblock records going back to 1900. It should also be noted that older records in the system may not be as complete as current harvest records. Furthermore, harvest on private lands and in certain licence types is not required to be reported to the RESULTS system.

17.1.1.1.4 RESULTS and VRI

The Reporting Silviculture Updates and Land Status Tracking System (RESULTS) application tracks silviculture information by managing the submission of openings, disturbances, silviculture activities and obligation declarations as required by the Forest and Range Practices Act.

Under RESULTS, data is submitted using an Electronic Submission Framework (ESF) that is linked to associated spatial information, ensuring consistency in geographic information. All data (including spatial data) is replicated in the B.C. Geographic Warehouse.

The RESULTS database is pivotal for TSR as it provides the attributes that drives managed stand yield generation, for determining managed stand ages, is the primary source for data for assess practices and trends related to retention and harvest system selection, and provides a spatial link between databases like ECAS/HBS through opening and timber mark.

RESULTS Forest Cover is provided at three critical milestones of at harvesting (denudation), at regeneration (after regeneration delay), and at free growing. This is a part of the Silviculture and Land Status Tracking data set, which includes tracking achievement of silviculture obligations on Crown Land.

Forest Cover is submitted before June 1 for areas where:

  • Where harvesting has been completed before March 31 of that year
  • Has met regeneration date up to March 31 of that year (the first survey which can take up to 7 years depending on FSP commitments)
  • Has not met regeneration requirements but the regeneration date has passed prior to March 31 of that year
  • Has met free growing date requirements up to March 31 of that year and to fulfill legal obligations (which can take up to 15 - 20 years depending on FSP commitments)
  • Free growing declaration has been made in accordance to FRPA 107 and FPPR 97; or,(the last survey which can take up to 15 - 20 years depending on FSP commitments)
  • Has not met free growing requirements but the free growing date has passed prior to March 31 of that year

As part of the Provincial Managed Stand Yield Table (MSYT) process RESULTS derived ages are calculated from the WHSE_FOREST_VEGETATION.RSLT_ACTIVITY_TREATMENT_UNIT table in the BCGW. Establishment date is calculated as the earliest of either the atu_start_date and the atu_completion_date and the final results age is difference between the current date (created in 2023) and the establishment date.

The RESULTS derived age (named rslt_age) along with proj_age_1 (renamed vri_ref_age) are summarized in the MSYT reference table (which categorizes the province for yield curve production).

17.1.1.1.5 Recent Harvest

The RESULTS database was created in 2003, and photo interpreters working on the VRI had to determine whether an opening not present in RESULTS was created prior to or after that date. Harvesting disturbances created after 2003 and not in RESULTS were given an OPENING_ID of 0 (zero) and harvesting disturbances created on or before January 01, 2003 and not in RESULTS will be given an OPENING_ID of -99. There are 40152 features in the 2025 VRI where the opening id is either 0 or -99 totaling ~450 000 ha of THLB provincially.

In the MSYT process we trap these openings and assign an age in the msyt_reference table and place them on an aggregate curve:

17.1.1.1.6 Retention Flag

The following query identifies VRI 2025 forest inventory polygons that are associated with reserve-designated RESULTS forest cover records and creates a lookup table linking VRI feature IDs to qualifying reserve areas. The query first builds a res table containing unique forest_cover_id values that meet specific reserve criteria, including group reserves (SILV_RESERVE_CODE = ‘G’) established after 2012, reserve-designated stands with valid stocking statuses and stocking types, and wildlife tree patches(SILV_RESERVE_OBJECTIVE_CODE = ‘WTR’) associated with reserve codes G or W. 2012 is designated the cut-off year for identify retention from RESULTS due to the poor quality of the data from years 2003 - 2011.

The resulting dataset (res) therefore represents all VRI polygons that can be traced to forest cover records meeting the specified reserve definitions, enabling subsequent analyses of reserve areas within the VRI inventory.

Code 
#####################retention###################################################
##Retention polygons in RESULTS
## use the reserve field as a flag and assign the VRI age to these in cutblock features


sql<-glue_sql("with res as (select
        distinct forest_cover_id, 
        1 as reserve
        from whse.rslts_forest_cover
        where 
        (   SILV_RESERVE_CODE IN ('G') 
            AND STOCKING_STATUS_CODE = 'MAT'

        ) 
        or 
        (   SILV_RESERVE_CODE IN ('G') 
            AND STOCKING_STATUS_CODE IN ('NP', 'MAT', 'IMM', 'RES') 
            AND STOCKING_TYPE_CODE IN ('NAT', 'FOR', 'BR')

17.1.1.2 Age Assignment Case Statement

In the following code chunk the Base dataframe is updated with a new variable titled age2026 (the rasterization column) and hierarchical age assignment case statement is executed to populate the variable.

The sequence of data source follows:

  1. Retention
  2. change detection
  3. ground survey ages
  4. psp survey ages
  5. results ages (with an exception for openings not in RESULTS)
  6. consolidated cut block ages
  7. Recent Harvest
  8. VRI ages
  9. -9997 for features with out ages

Features without ages are assigned an age value of -9997.

There is a potential for ground sample sites (particularly those related to VRI audits) and permanent sample plots to have been logged after the final recorded visit to the site. In those cases the change detection age apply.

The RESULTS database was created in 2003, and a photo interpreter working on a given inventory update had to determine whether an opening not present in RESULTS was created prior to or after that date (2003). Harvesting disturbances created after 2003 and not in RESULTS are given an OPENING_ID of 0 (zero) and harvesting disturbances created on or before January 01, 2003 and not in RESULTS are given an OPENING_ID of -99.

When determining ages for openings with invalid opening_ids (0,-99) the process prioritizes harvest year derived ages from the consolidated cut block data set otherwise RESULTS derived ages are prioritized over consolidated cut block derived ages. Using the consolidated cut block layer allows for the leveraging of the change detection mapping for all openings created post 1998 that are not identified in RESULTS. The process leverages the msyt_2025.integration_final table that identifes these opening as stand_type 21 and the assigns the recent_harv_age.

Since 2015 inventory attribution (basal area, live stems per ha) has been adjusted based on fire severity mapping from the previous season. A fire update flag has been added to the Base dataframe to aid in decisions related to age adjustments for fires. Approximately 15% (96611 features) of the features within openings have had a fire update since 2015.
